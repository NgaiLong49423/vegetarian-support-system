# Changelog Reference

Use this reference for meaningful project/release/milestone change history.

## 1. Responsibility

Changelog records WHAT CHANGED across versions/releases/milestones according to repository convention.

It does not replace:

- SRS/requirements for current required behavior;
- Decision Records for why a significant choice was made;
- Git history for every code-level change;
- architecture documentation for current system structure.

## 2. Record Meaningful Changes

Prefer user- or maintainer-relevant entries such as significant added, changed, fixed, or removed behavior.
Do not flood the changelog with variable renames, formatting fixes, or routine refactors unless repository policy requires them.

## 3. Requirement Removal History

A changelog/change-history artifact may record that a requirement was deferred, retired, or removed from the active baseline when this is useful.
It is not the only permitted history mechanism; follow repository convention.

## 4. Versioning Boundary

Do not invent version numbers or dates.
If a dedicated metadata/versioning skill exists, defer version policy and bump decisions to it.
