# Contributing Reference

Use this reference for collaboration and contribution workflow.

## Typical Responsibilities

`CONTRIBUTING.md` may own:

- branch strategy;
- commit/PR conventions;
- issue workflow;
- code review expectations;
- merge/approval rules;
- contributor responsibilities;
- documentation-update expectations;
- handling uncertain requirements/decisions during contribution.

Keep enforceable rules explicit. Avoid aspirational rules the team does not actually follow.

## Boundary with DEVELOPMENT.md

`CONTRIBUTING.md` explains how people collaborate.
`DEVELOPMENT.md` explains how developers technically work with the system.

Do not duplicate detailed build/test/migration commands here when `DEVELOPMENT.md` owns them; link instead.

## Governance

If repository governance delegates approval authority or decision roles, preserve those rules. The documentation skill must not invent or override team authority.
