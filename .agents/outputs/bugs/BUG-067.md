# BUG-067 — Adapter AI soạn bài chấp nhận phản hồi chưa hoàn tất của provider

- **Trạng thái:** RESOLVED
- **Khu vực:** Backend/AI/Recipe assistance
- **Mức độ:** Medium
- **Ngày phát hiện:** 2026-10-25
- **Ngày cập nhật:** 2026-10-25
- **Bối cảnh:** Rà soát xử lý lỗi AI liên quan FR-10.
- **Nhánh/commit:** `feature/16-ai-feature-entitlements`, `7179559`.
- **Yêu cầu/Issue:** FR-10, FR-21, BR-04; [Issue #16](https://github.com/NgaiLong49423/vegetarian-support-system/issues/16).

## Mong đợi

Phản hồi provider chưa hoàn tất không được coi là kết quả thành công. Adapter phải kiểm tra trạng thái hoàn tất trước khi trả nội dung cho service, như các phương thức chat và recommendation hiện có.

## Thực tế và bằng chứng

`GeminiAiClient.generateRecipeText` chỉ kiểm tra `response.text()` không rỗng, không kiểm tra `finishReason`. HTTP provider local trả 200 với JSON text hợp lệ và `finishReason=MAX_TOKENS`; gọi adapter thật cho kết quả `INCOMPLETE_RECIPE_ACCEPTED=true`. Do text có thể vẫn parse được, kiểm tra JSON ở service không thay thế được kiểm tra trạng thái provider.

Các phương thức chat/recommendation đã có kiểm tra STOP. BUG-075 hiện có nói về mã lỗi chatbot và đã sửa riêng chatbot; đây là thiếu kiểm tra ở phương thức soạn bài, không phải lỗi chatbot đó tái xuất hiện.

## Tái hiện

1. Cho HTTP server local trả candidate có JSON description/steps và `finishReason=MAX_TOKENS`.
2. Khởi tạo `GeminiAiClient` dùng base URL local và API key tổng hợp.
3. Gọi `generateRecipeText`.
4. Quan sát adapter trả text thay vì ném lỗi phản hồi không hợp lệ.

## Môi trường

Windows, Java 25 biên dịch source theo cấu hình repository, SDK Gemini hiện tại; provider HTTP local có kiểm soát. Không gọi Google hoặc dùng khóa thật.

## Nguyên nhân

Nhánh RECIPE_TEXT bỏ qua metadata hoàn tất của candidate.

## Cách xử lý

Đã kiểm tra finishReason trước khi lấy nội dung RECIPE_TEXT; các trạng thái chưa hoàn tất trả lỗi INVALID_RESPONSE. Service soạn bài giữ phân loại này thành `502 AI_RESPONSE_INVALID`, thay vì chuyển thành lỗi outage 503. Không đưa telemetry FR-11 vào nhánh FR-10.
