# BUG-012 — Schema báo cáo lưu trạng thái và mã lý do lỗi thời

- **Trạng thái:** RESOLVED
- **Khu vực:** Backend/Cơ sở dữ liệu báo cáo
- **Mức độ:** Trung bình (Medium)
- **Ngày phát hiện:** 2026-10-06
- **Ngày cập nhật:** 2026-10-06
- **Bối cảnh phát hiện:** Triển khai lưu báo cáo Recipe Post theo Issue #31.
- **Nhánh/Commit:** `feature/31-recipe-report-submission` / Chưa xác định
- **Yêu cầu:** FR-26, FR-27
- **Issue:** 31
- **PR:** Chưa xác định

## Biểu hiện

Schema REPORT từ baseline V1 chỉ chấp nhận trạng thái `PENDING`, `PROCESSING`, `RESOLVED`, `REJECTED` và mã lý do `NON_VEGAN`; các giá trị trạng thái và taxonomy này không khớp baseline yêu cầu hiện hành (`OPEN`, `IN_REVIEW`, `RESOLVED` và sáu mã lý do tại FR-27).

## Kết quả mong đợi

Schema sau toàn bộ migration chấp nhận đúng trạng thái và mã lý do của SRS; dữ liệu cũ được chuyển đổi mà không sửa migration V1 đã có.

## Kết quả thực tế

Trước khi có V9, schema chỉ cho phép các trạng thái/mã lý do cũ. V9 đã chuyển dữ liệu cũ, cập nhật các constraint/index; migration đã chạy thành công trên SQL Server Testcontainer trong integration test của Issue #31.

## Bằng chứng

- `app/mamxanh-backend/src/main/resources/db/migration/V1__baseline_schema.sql`: `CK_REPORT_status`, `CK_REPORT_reason_code`, default và unique indexes dùng giá trị cũ.
- `docs/requirements/SRS.md` mục 3.11–3.12 và `docs/requirements/srs/FUNCTIONAL-REQUIREMENTS.md` FR-26/27: yêu cầu hiện hành.
- `app/mamxanh-backend/src/main/resources/db/migration/V9__align_recipe_report_contract.sql`: migration bổ sung ánh xạ dữ liệu và cập nhật constraint/index.
- `RecipeReportIntegrationTest`: Flyway chạy migration trên SQL Server Testcontainer; 5/5 test pass (0 failures, 0 errors), gồm lưu báo cáo `OPEN` và đọc/ghi taxonomy mới.

## Cách tái hiện

1. Khởi tạo schema chỉ đến V1 hoặc đọc các ràng buộc REPORT trong V1.
2. Đối chiếu giá trị CHECK/default/index với trạng thái và mã lý do trong SRS hiện hành.

## Môi trường

Repository trên nhánh `feature/31-recipe-report-submission`, ngày 2026-10-06; Docker Desktop Linux Engine 29.8.1, SQL Server 2019 Testcontainer theo digest đã ghim trong repo.

## Nguyên nhân

Baseline schema được tạo trước khi trạng thái và nhóm lý do hiện hành được thống nhất; chưa xác định thêm.

## Hướng xử lý

Đã thêm migration append-only V9 và cập nhật snapshot `database/schema.sql` để giữ tương thích với FR-26/27 mà không sửa migration V1.

## Kiểm chứng

Đã chạy `mvn -Dtest=RecipeReportIntegrationTest test`: 5 test pass, 0 failures/errors/skipped. Migration V9 được áp dụng khi Spring context khởi tạo SQL Server sạch; API tạo báo cáo `OPEN`, lưu mã lý do mới, duplicate `OPEN`/`IN_REVIEW` bị chặn và bài giữ `PUBLISHED`.
