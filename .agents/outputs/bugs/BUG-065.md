# BUG-065 — Chatbot dùng timeout Gemini chung 60 giây vượt giới hạn 10 giây

- **Trạng thái:** `RESOLVED`
- **Khu vực:** Backend/AI/Chatbot
- **Mức độ:** Chưa xác định
- **Ngày phát hiện:** 2026-10-24
- **Ngày cập nhật:** 2026-10-24
- **Ngữ cảnh:** Phân tích và triển khai FR-02 trên nhánh `feature/10-guest-chatbot-rate-limit`, baseline `775de7c`.
- **Yêu cầu:** FR-02, FR-51, NFR-18.
- **Issue liên quan:** [#10](https://github.com/NgaiLong49423/vegetarian-support-system/issues/10); chưa tạo Bug Issue riêng.

## Triệu chứng và hành vi mong đợi

NFR-18 yêu cầu timeout dịch vụ Gemini tối đa 10 giây và phản hồi lỗi thân thiện. `GeminiAiClient.answerChat` dùng chung client cấu hình `DEFAULT_TIMEOUT_MILLIS = 60_000`, không có timeout riêng cho chat. Frontend chờ tối đa 12 giây không tự hủy lời gọi provider ở Backend.

## Bằng chứng và tái hiện

- Trên baseline, constructor `GeminiAiClient` tạo client với timeout 60.000 ms; `answerChat` gọi `client.models.generateContent` mà không ghi đè HTTP options.
- `recipesApi.chat` dùng timeout trình duyệt 12.000 ms; hai cơ chế không thay thế nhau.
- Kiểm thử `chatDeadlineStopsASlowProviderWithoutWaitingForTheSharedSixtySecondTimeout` dùng HTTP server local trì hoãn 20 giây và client chung timeout 60 giây để kiểm tra deadline riêng của chat; không gọi Gemini thật.

## Môi trường và nguyên nhân

Spring Boot, Java 21, Google Gen AI Java SDK 1.76.0. Timeout chung được dùng cho nhiều workflow; chat chưa giới hạn riêng theo NFR-18. Chưa khẳng định mọi request thật đều mất 60 giây.

## Cách xử lý

Working tree bổ sung HTTP timeout riêng 10.000 ms và một attempt cho `answerChat`, giữ nguyên timeout các workflow khác. Log kỹ thuật chỉ chứa loại lỗi hoặc HTTP status, không chứa prompt, thông báo provider thô hoặc credential.

## Kiểm chứng

Bản cuối đạt 46/46 test limiter, service, HTTP/security/CORS và Gemini client; thêm 1/1 integration test dùng SQL Server thật đạt. Test HTTP server local trì hoãn 20 giây xác nhận chat dừng trong giới hạn đo dưới 12 giây (bao gồm overhead kiểm thử), chỉ có một lời gọi và không chờ timeout chung 60 giây. Cấu hình request thực tế dùng timeout 10.000 ms.

Frontend đạt 10/10 browser test, TypeScript và build; kiểm thử qua root Compose xác nhận `429` và `Retry-After`. Các bằng chứng này xác nhận sửa timeout và xử lý lỗi; không chứng minh SLA NFR-03 hoặc chất lượng Gemini thật. Lần gọi provider thật trả `503 AI_PROVIDER_UNAVAILABLE`, log an toàn ghi chuỗi loại lỗi `GenAiIOException/InterruptedIOException/IOException`; chưa xác nhận phản hồi thành công với provider thật.
