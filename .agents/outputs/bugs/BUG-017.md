- **Khu vực:** Backend/Validation API bình chọn

- **Ngày ghi nhận:** 2026-10-11

## Biểu hiện

GET, PUT và DELETE `/api/v1/recipes/{recipeId}/reaction` trả 500 thay vì lỗi đầu vào khi `recipeId` bằng 0 hoặc -1.

## Kết quả mong đợi

ID phải tối thiểu 1 theo `@Min(1)`. Đầu vào không hợp lệ trả 400 với ProblemDetail, không gọi service hoặc thay đổi dữ liệu.

## Kết quả thực tế trước sửa

Sáu yêu cầu HTTP thật với token Member hợp lệ đều trả `500 INTERNAL_ERROR`: GET/PUT/DELETE cho ID 0 và -1. PUT dùng payload hợp lệ `{"reactionType":"LIKE"}`.

## Bằng chứng

- Backend local tại 8081 xác nhận status/code cho cả sáu yêu cầu trước sửa ngày 11/10/2026.
- Controller dùng `@Validated` ở cấp class; validation AOP ném `ConstraintViolationException`, không đi qua nhánh validation MVC của `ResponseEntityExceptionHandler` và bị xử lý như lỗi không mong đợi.
- Generated OpenAPI mô tả response 400 và parameter có minimum 1.

## Cách tái hiện

1. Đăng nhập bằng tài khoản Member local hợp lệ.
2. Gọi GET `/api/v1/recipes/0/reaction`, PUT cùng path với payload LIKE, và DELETE cùng path.
3. Lặp lại với ID -1; quan sát HTTP 500 trước sửa.

## Môi trường

Java 21, Spring Boot, Backend profile `local` tại 8081, SQL Server local; không bật `local-reset`.

## Nguyên nhân

Annotation validation cấp class kích hoạt AOP thay vì validation tham số MVC hiện hành; exception không được phân loại thành lỗi 400.

## Cách xử lý

Bỏ `@Validated` ở `RecipeReactionController`, giữ `@Min(1)` và `@Valid`, dùng validation MVC có sẵn. Bổ sung `RecipeReactionControllerTest` xác nhận lỗi đầu vào không gọi service, payload sai trả 400, và contract thành công/no-store.
