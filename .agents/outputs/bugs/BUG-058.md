# BUG-058 — Kiểm tra mã lỗi API không tương thích với kiểu TypeScript tùy chọn

- **Trạng thái:** `RESOLVED`
- **Khu vực:** Frontend/AI recipe planner
- **Mức độ:** Medium
- **Ngày phát hiện:** 2026-10-23
- **Ngày cập nhật:** 2026-10-23
- **Nhánh:** `codex/ai-cooking-step-details`
- **Issue/PR:** PR #181; không có Issue riêng cho lỗi biên dịch này.

## Triệu chứng

Frontend CI dừng ở bước Type-check trong `AiRecipePlanner.tsx` khi phân loại lỗi tạo hướng dẫn nấu. Mã xử lý lỗi phải nhận cả `ApiError.code` có thể vắng mặt.

## Mong đợi và thực tế

Mong đợi: Frontend biên dịch được khi mã lỗi chưa được cung cấp, đồng thời nhận diện chính xác các mã lỗi có hỗ trợ.

Thực tế: `ApiError.code` có kiểu `string | undefined` nhưng được truyền trực tiếp vào `Array.includes`, vốn yêu cầu `string`; TypeScript báo TS2345 tại hai điều kiện và job Frontend fail.

## Bằng chứng và tái hiện

Trên GitHub Actions của PR #181, job Frontend fail ở bước `Type-check` với lỗi TS2345 tại `src/pages/AiRecipePlanner.tsx` dòng 141 và 143 (trên commit CI lúc đó). Điều kiện lỗi dùng `['...'].includes(cause.code)`.

## Môi trường và nguyên nhân

React/TypeScript Frontend, `npm run lint` (`tsc --noEmit`). Kiểu của thuộc tính `ApiError.code` cho phép `undefined`, nhưng helper `Array.includes` không nhận giá trị đó.

## Cách xử lý

So sánh `cause.code` trực tiếp với từng mã được hỗ trợ thay vì truyền giá trị tùy chọn vào `Array.includes`.

## Kiểm chứng

Sau khi sửa, `npm run lint` hoàn tất với exit code 0 và `npm run build` hoàn tất với exit code 0. Build còn cảnh báo hiện hữu về kích thước chunk trên 500 kB; cảnh báo không làm build thất bại. Chờ GitHub Actions chạy lại trên commit cập nhật để xác minh CI.
