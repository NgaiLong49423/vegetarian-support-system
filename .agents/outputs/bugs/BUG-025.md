# BUG-025 — CI không tải font Git LFS cho chức năng xuất lịch PDF

- **Trạng thái:** `RECORDED`
- **Khu vực:** Frontend/CI/PDF
- **Mức độ:** Medium
- **Ngữ cảnh phát hiện:** Đồng bộ develop và kiểm tra lại PR #135 / FR-33 / Issue #38.
- **Commit phát hiện:** `c419e7b`.
- **Ngày phát hiện/cập nhật:** 2026-10-14.

## Triệu chứng và kết quả mong đợi

PDF cần font Noto Sans thật để hiển thị tiếng Việt. Checkout trên runner CI phải tải nội dung Git LFS trước khi build và kiểm tra PDF.

## Kết quả thực tế và bằng chứng

`git show c419e7b:app/mamxanh-frontend/public/fonts/NotoSans-Regular.ttf` trả pointer Git LFS gồm ba dòng, size khai báo 569208 byte. `.gitattributes` của Frontend quy định `*.ttf` dùng LFS. Các bước `actions/checkout@v4` của job Frontend và Docker Development chưa bật `lfs`, nên checkout mặc định không tải font thật; file được Vite copy nguyên vào public assets.

Local worktree đã có font thật nên build/test local trước đây không phát hiện khác biệt này. Chưa có bằng chứng CI fail vì PR đang bị merge conflict ngăn workflow CI chạy.

## Tái hiện

1. Checkout commit trên runner với cấu hình checkout mặc định của hai job trên.
2. Kiểm tra file NotoSans-Regular.ttf: nội dung là pointer LFS.
3. Build Frontend và yêu cầu xuất PDF; thư viện cần dữ liệu TTF thật, không phải pointer.

## Môi trường và nguyên nhân

GitHub Actions, actions/checkout@v4, Vite và jsPDF 4.2.1. Thiếu bước tải Git LFS cho asset mới mà FR-33 dùng khi chạy.

## Cách xử lý

Trong cùng PR #135, bổ sung `lfs: true` cho checkout của Frontend và Docker Development. Giữ quy tắc LFS hiện hành, không đổi font hoặc dependency.

## Kiểm chứng

Chưa xác minh checkout trên GitHub runner sau sửa. Cần kiểm tra CI của commit đồng bộ và tests tải PDF trước khi đánh dấu RESOLVED.
