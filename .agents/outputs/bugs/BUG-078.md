# BUG-078 — Hàng đợi RAM làm mất telemetry khi ghi SQL lỗi hoặc queue đầy

- **Trạng thái:** RESOLVED
- **Khu vực:** Backend/AI telemetry
- **Mức độ:** High
- **Ngày phát hiện:** 2026-10-28
- **Ngày cập nhật:** 2026-10-28
- **Bối cảnh:** Đối chiếu các phần còn thiếu của FR-11 theo yêu cầu người dùng.
- **Nhánh/commit:** `feature/17-ai-usage-telemetry`, checkpoint `def92605`; code gốc tại `79394340`.
- **Yêu cầu/Issue:** AC-11.1, BR-04, NFR-22; [Issue #17](https://github.com/NgaiLong49423/vegetarian-support-system/issues/17). Chưa có Bug Issue riêng.

## Mong đợi

Metadata của phản hồi AI đã được ứng dụng xác nhận thành công phải có bản sao bền vững; lỗi DB tạm thời, queue đầy hoặc restart không được làm mất bản sao duy nhất. Không lưu prompt/answer, không giữ dữ liệu quá 90 ngày.

## Thực tế và bằng chứng

Listener tại checkpoint chỉ đưa event vào executor RAM có hai worker và queue 500. Nhánh catch khi enqueue hoặc ghi SQL lỗi chỉ ghi log; không lưu pending event để gửi lại. `@PreDestroy` chỉ chờ tối đa 10 giây và không bảo vệ khi process dừng cưỡng bức. README cũ cũng ghi rõ giới hạn này.

## Cách tái hiện

1. Dùng writer lỗi SQL hoặc chặn cả hai worker và lấp đầy queue.
2. Phát event sau phản hồi AI thành công.
3. Writer/enqueue lỗi nhưng không có bản ghi SQL hoặc bản sao bền vững; restart không thể phục hồi event.

## Môi trường và nguyên nhân

Spring Boot, SQL Server, executor riêng. Nguyên nhân là buffer RAM là bản sao duy nhất trước khi SQL commit.

## Xử lý

Đã bổ sung file pending chỉ có metadata, force nội dung và atomic rename trước khi xác nhận; volume riêng trong root Compose; replay theo UUID, chỉ acknowledge sau SQL commit; disk không ghi được trả 503 thay vì xác nhận thiếu accounting. Retention áp dụng cả SQL và file pending. Không bảo đảm phục hồi nếu chính storage bền vững bị mất/hỏng.

## Kiểm chứng

- `AiTelemetrySpoolTest`: 6/6, gồm recovery từ disk, lỗi DB, queue đầy, stale replay sau acknowledge, disk lỗi và retention.
- Nhóm `AiTelemetrySpoolTest,AiTelemetryServiceTest,AiCookingGuideServiceTest,AiTelemetryIntegrationTest`: 39/39; SQL Server thật kiểm tra idempotence, commit độc lập, quyền truy cập và phục hồi pending.
- Test opt-in `FR11 live Gemini accounting survives a SQL outage and forced Backend restart on the Compose volume` đã qua: gọi Gemini 3.8 thật khi SQL dừng, xác nhận file pending trước khi kill Backend, khởi động lại và kiểm tra đúng một bản ghi SQL cùng báo cáo Admin. Không lưu prompt/answer hoặc credential vào file.
- Bổ sung chốt `isPending` trước khi writer xử lý danh sách replay cũ; giữ nguyên assertion đếm SQL. Không tăng timeout hoặc bỏ kiểm tra nghiệp vụ để pass.
- Thay đổi vẫn local/chưa commit; phê duyệt cấu trúc và nghiệm thu main là bước riêng chưa thực hiện.
