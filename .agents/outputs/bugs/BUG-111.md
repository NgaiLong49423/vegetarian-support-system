# BUG-111 — Endpoint dinh dưỡng lịch ăn lỗi khi BMI đã lưu bị null

- **Trạng thái:** RESOLVED

- **Ngày cập nhật:** 2026-11-20
- **Bối cảnh:** Phân tích log Backend do người dùng cung cấp sau khi khởi chạy local.
- **Nhánh/commit:** Chưa xác định.
- **Yêu cầu/Issue:** Chưa xác định.

## Hiện tượng và mong đợi
Khi Frontend tải chỉ số dinh dưỡng cho kế hoạch ăn tại `GET /api/v1/meal-plans/2026-11-16/nutrition`, Backend trả lỗi nội bộ lặp lại. Endpoint cần trả kết quả hoặc lỗi nghiệp vụ phù hợp, không ném NullPointerException.

## Bằng chứng hiện có
- Log ngày 20/11/2026 ghi `Unhandled exception while processing /api/v1/meal-plans/2026-11-16/nutrition` và `Cannot invoke BigDecimal.compareTo(...) because "bmi" is null`.
- Stack trace: `NutritionCalculationService.bmiCategory:32` → `NutritionProfileService.response:240` → `targetsIfProfileExists:174` → `MealPlanNutritionService.analyze:70`.
- `hasSavedProfile()` chỉ kiểm tra ngày sinh, giới tính, chiều cao, cân nặng, mức hoạt động và consent; không kiểm tra `nutrition_bmi`. `response()` lấy BMI trực tiếp từ `user.getNutritionBmi()` rồi gọi `bmiCategory(bmi)`.
- Migration V25 có backfill BMI cho hồ sơ đã consent có chiều cao/cân nặng. Chưa có truy vấn database để xác định user phát sinh lỗi, giá trị các trường của user hoặc lý do cột `nutrition_bmi` hiện null.
- Đã tìm thấy nguồn dữ liệu trực tiếp trong `R__demo_sample_data_50_member_activity.sql`: fixture cập nhật chiều cao, cân nặng và `health_data_consent = 1` cho `demo-customer` cùng các demo customer khác nhưng trước đây không gán `nutrition_bmi`. Repeatable demo migration chạy sau V25 nên các dòng do fixture này cập nhật không được V25 backfill lại.
- Backend khởi động thành công; log báo Flyway xác thực 69 migration, áp dụng ba repeatable migration và Tomcat chạy trên cổng 8080. Đây không phải lỗi startup hay Flyway.
- Log mới lúc 22:02 ngày 20/11/2026 tái hiện cùng stack trace sau khi Backend khởi động lại. Lần này Flyway báo schema đã up to date, không có migration cần chạy; việc restart không tự khắc phục dữ liệu BMI null.

## Tái hiện
1. Có Member đủ điều kiện dinh dưỡng với các trường khiến `hasSavedProfile()` trả true nhưng `nutrition_bmi` null.
2. Tải kế hoạch ăn ngày `2026-11-16` để gọi `GET /api/v1/meal-plans/2026-11-16/nutrition`.
3. `targetsIfProfileExists()` gọi `response()`, và `bmiCategory(null)` ném NullPointerException.

## Môi trường
Windows, Java 21.0.12, Spring Boot 4.1.1, SQL Server local `MamXanhDB`; thời điểm theo log 20/11/2026. Không truy cập database hoặc token người dùng trong lượt chẩn đoán.

## Nguyên nhân
Đã xác nhận nguyên nhân cho demo customers: repeatable fixture đặt hồ sơ consented nhưng bỏ trống BMI; V25 backfill chạy trước repeatable fixtures. Không thể xác nhận email/user cụ thể trong log vì stack trace không ghi ID người dùng.

## Xử lý
Đã cập nhật fixture để gán BMI theo chiều cao/cân nặng và bổ sung fallback chỉ khi BMI lưu bị null. BMI có sẵn vẫn được giữ nguyên; fallback chỉ đọc và không ghi database. Chưa xác minh repeatable SQL trên SQL Server local vì cổng 1433 hiện không kết nối được.

Kết nối SQL Server local không khả dụng (`localhost:1433` từ chối kết nối), nên chưa thể chạy lại Flyway repeatable trên database của người dùng; seed đã được sửa để áp dụng ở lần khởi động tiếp theo với SQL Server local hoạt động.
