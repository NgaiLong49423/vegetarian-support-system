## Triệu chứng

Sau integration suite báo cáo Recipe, các suite Auth lỗi khi xóa `USER` vì còn Recipe Post tham chiếu qua `FK_RECIPE_POST_USER`.

## Hành vi mong đợi

Integration test xóa report, recipe và user fixture sau mỗi ca để test suite tiếp theo chạy độc lập trên SQL Server.

## Hành vi thực tế

`RecipeReportIntegrationTest` chỉ dọn dữ liệu trước mỗi test. Test cuối trong class để lại Recipe Post và author trong database; các suite sau không thể xóa user.

## Bằng chứng

- Lượt `clean verify` trước khi sửa: 255 tests, 0 failures, **49 errors** do `FK_RECIPE_POST_USER` khi `EmailRegistrationIntegrationTest.deleteUsers` và `PasswordLoginIntegrationTest.deleteUsers` xóa user.
- Sau khi thêm cleanup sau mỗi test: `clean verify` pass **255 tests**, 0 failures/errors/skips.
- SQL Server Testcontainer thật khởi động và chạy Flyway đến migration V9.

## Cách tái hiện

Chạy `mvn clean verify` trên nhánh Issue #31 trước khi có cleanup sau mỗi test; auth suite sau `RecipeReportIntegrationTest` gặp lỗi khóa ngoại khi xóa users.

## Môi trường và nguyên nhân gốc

- **Môi trường:** Maven, Java 26, SQL Server Testcontainer theo image/digest đã pin.
- **Nguyên nhân gốc:** Integration test báo cáo thiếu teardown fixture sau mỗi ca.

## Xử lý và kiểm chứng

- **Xử lý:** Thêm `@AfterEach` xóa report theo recipe, xóa recipe, rồi xóa các user fixture của Issue #31.
- **Kiểm chứng:** `mvn clean verify` pass; 255 tests và cả bốn JaCoCo BUNDLE metrics đều vượt 80%.
