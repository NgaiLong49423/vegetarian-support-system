# BUG-021 — Ghi nhận lượt xem trả 503 vì lấy khóa trước khi transaction SQL được kích hoạt

- **Trạng thái:** `RESOLVED`
- **Khu vực:** Backend/Ghi nhận lượt xem
- **Mức độ:** High
- **Ngữ cảnh phát hiện:** Chạy CI SQL Server và Compose cho FR-58 trong giai đoạn 6.
- **Nhánh/commit:** `feature/57-recipe-view-analytics`, `27be853`.
- **Requirement/Issue/PR:** FR-58 AC-58.1/58.2/58.3; Issue #57; [PR #123](https://github.com/NgaiLong49423/vegetarian-support-system/pull/123).
- **Ngày phát hiện:** 2026-10-12
- **Ngày cập nhật:** 2026-10-12

## Triệu chứng và hành vi mong đợi

Guest/Member mở công thức công khai lần đầu phải nhận `200`, tạo một sự kiện và tăng bộ đếm. Reload cùng người xem trong cửa sổ trả `200`, `counted=false`.

## Hành vi thực tế và bằng chứng

Tại commit `27be853`, [CI run 38191502372](https://github.com/NgaiLong49423/vegetarian-support-system/actions/runs/38191502372) ghi nhận 5 failure và 5 error trong các test ghi nhận lượt xem; service trả `RECIPE_VIEW_UNAVAILABLE`. Test browser–API–SQL trong Compose nhận `503` thay vì `200`. Các ca mapping/time-window dùng mock trước đó không phát hiện lỗi này.

Log không in mã trả về cụ thể của `sp_getapplock`; không suy rằng đã quan sát trực tiếp mã `-999`.

## Cách tái hiện

1. Build source `27be853` bằng root Compose và chạy Flyway trên SQL Server.
2. Tạo công thức công khai, rồi mở `/cong-thuc/id/<id>` bằng Guest mới.
3. Quan sát `POST /api/v1/recipes/<id>/views` trả `503`; bộ đếm không tăng.
4. Chạy `RecipeViewIntegrationTest` hoặc `recipe-views-real-stack.spec.ts` để tái hiện có assertion.

## Môi trường và nguyên nhân gốc

- **Môi trường:** GitHub Actions Ubuntu, SQL Server image đã pin của Testcontainers/Compose, Microsoft JDBC, Spring JPA transaction.
- **Phân tích nguyên nhân:** Service gọi `sp_getapplock` là thao tác database đầu tiên trong transaction. SQL Server yêu cầu transaction đã tồn tại cho `LockOwner=Transaction`; implicit transaction được khởi động bởi statement đọc bảng, không phải lời gọi procedure này. Các test SQL ghi nhận đã pass sau khi thêm lần đọc trước khóa.
- **Nguồn kỹ thuật:** [sp_getapplock](https://learn.microsoft.com/en-us/sql/relational-databases/system-stored-procedures/sp-getapplock-transact-sql), [implicit transactions](https://learn.microsoft.com/en-us/sql/t-sql/statements/set-implicit-transactions-transact-sql).

## Xử lý và kiểm chứng

- **Xử lý trong phạm vi Issue #57:** Đọc công thức công khai để kích hoạt transaction trước khóa; đọc lại bộ đếm sau khi lấy khóa để không trả số cũ nếu phải chờ lượt ghi khác. Giữ transaction do Spring quản lý, không tạo transaction lồng bằng `BEGIN TRANSACTION` thủ công.
- **Regression:** Thêm service test trả bộ đếm mới sau khi chờ khóa. Các ca first-view, dedup, concurrency và rollback trên SQL/Compose đã có từ trước và fail ở run nêu trên.
- **Kiểm chứng:** Backend [CI run 38192001561](https://github.com/NgaiLong49423/vegetarian-support-system/actions/runs/38192001561/job/114626562065), source `6a20c24`: `clean verify` có 425 tests pass, không fail/error/skip, bao gồm 13 test SQL của `RecipeViewIntegrationTest` về first-view, dedup, concurrency và rollback. JaCoCo đạt đủ bốn ngưỡng >80%. Test Compose đã qua ghi lần đầu, reload và đối chiếu hash/counter SQL trước khi dừng ở locator tìm kiếm cũ; lỗi locator được xử lý riêng trong cùng PR, không phải lỗi 503. Xác nhận sửa trên feature branch, chưa nghiệm thu Issue trên `main`.
