## Kết quả mong đợi

Contract generated của `POST /api/v1/recipes/ai/chat`, annotation `AiChatController:49` và hướng dẫn API mô tả phản hồi Gemini thiếu/không hoàn chỉnh là `502 AI_RESPONSE_INVALID`; lỗi dịch vụ hoặc timeout là `503 AI_PROVIDER_UNAVAILABLE`.

## Kết quả thực tế và bằng chứng

Provider HTTP local trả 200 với candidate có text `partial`, `finishReason=MAX_TOKENS`. Gọi đúng `GeminiAiClient.answerChat` qua `AiChatService.answer` hiện tại: nhận AppException `AI_PROVIDER_UNAVAILABLE`, HTTP mapping 503. Kết quả thí nghiệm: `TRUNCATED_PROVIDER http=503 code=AI_PROVIDER_UNAVAILABLE`.

`GeminiAiClient` ném cùng `AiProviderException` khi phản hồi thiếu/không hoàn chỉnh và khi lỗi truyền tải. Nhánh catch trong `AiChatService` chuyển tất cả sang 503. Trường hợp JSON không hợp lệ ở bước parse sau đó lại dùng 502. Giao diện vì thế thông báo sự cố dịch vụ cả khi provider đã phản hồi nhưng dữ liệu không hoàn chỉnh.

## Cách tái hiện

1. Cho HTTP provider kiểm soát trả 200 với finishReason MAX_TOKENS và nội dung dở dang.
2. Gọi GeminiAiClient thật qua AiChatService, dùng mock cho phụ thuộc dữ liệu/account và Guest không cá nhân hóa.
3. Đối chiếu mã AppException và HTTP mapping với response 502 của generated OpenAPI.

## Môi trường và nguyên nhân

Windows, Java local, Google Gen AI SDK 1.76.0, server HTTP local; không dùng key hoặc Gemini live. Kiểm chứng đường đi SDK/service và ánh xạ ErrorCode, chưa gọi Controller HTTP trong lượt này vì Docker Desktop đang tắt. Lỗi phân loại response là finding riêng với BUG-073 về log, không kết luận nó gây toàn bộ lỗi live trước đó.

## Cách xử lý

AiProviderException phân biệt INVALID_RESPONSE với lỗi truyền tải/provider. AiChatService ánh xạ phản hồi bị cắt/thiếu sang 502 AI_RESPONSE_INVALID, lỗi provider/timeout vẫn là 503. Lỗi HTTP 429 từ Google không bị nhầm với bộ đếm Guest 429 của ứng dụng.

Bản sửa hiện ở working tree; chưa commit hoặc nghiệm thu trên main.
