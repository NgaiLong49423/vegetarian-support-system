# BUG-018 — Luồng đăng công thức có thể lưu ảnh xem trước thay cho ảnh đã upload

- **Trạng thái:** `RESOLVED`
- **Khu vực:** Frontend/Recipe media/Direct publishing
- **Mức độ:** Unknown
- **Ngữ cảnh phát hiện:** Đồng bộ PR #100 (FR-25) với `develop`.
- **Nhánh/commit:** PR #100 tại `e28636f`; baseline `develop` tại `3a1ab92`.
- **Requirement/Issue/PR:** FR-25, FR-14; [Issue #30](https://github.com/NgaiLong49423/vegetarian-support-system/issues/30); [PR #100](https://github.com/NgaiLong49423/vegetarian-support-system/pull/100).
- **Ngày phát hiện:** 2026-10-11
- **Ngày cập nhật:** 2026-10-11

## Triệu chứng

Luồng upload Frontend đọc sai response Backend, rồi chuyển sang URL ảnh xem trước `blob:`. FR-25 đưa URL này vào payload xuất bản và lưu `RECIPE_MEDIA`; ảnh xem trước chỉ có ý nghĩa trong trình duyệt đang mở.

## Hành vi mong đợi

Đọc đúng `data.blobUrl` và `data.mimeType` của Backend. Chỉ gửi tham chiếu ảnh upload thành công khi xuất bản; ảnh xem trước do upload thất bại phải được thông báo và không gửi để lưu bài viết.

## Hành vi thực tế

`recipeMediaApi.ts` đọc `response.data.result`, khai báo `url`, `contentType`, `size`; Backend trả `data` với `blobUrl`, `mimeType`, `sizeBytes`. `RecipeImageUploader.tsx` bắt lỗi và tạo `URL.createObjectURL(file)`. `CreateRecipe.tsx` chỉ kiểm tra ảnh bìa rồi đưa `m.url` vào `media[].blobUrl`.

## Bằng chứng

- Generated OpenAPI artifact `openapi-runtime-38066034325-1`, ID `11674198503`, từ [CI run 38066034325](https://github.com/NgaiLong49423/vegetarian-support-system/actions/runs/38066034325), có SHA `3a1ab928aab44f4b96ae14d9b79b5e54f84010f1`: `POST /api/v1/recipes/media/upload` trả schema `ApiResponseUploadImageResponse`, trường `data` có schema `UploadImageResponse` với `blobUrl`, `mimeType`, `sizeBytes`.
- `common/response/ApiResponse.java`, `recipe/controller/RecipeMediaController.java`, `recipe/dto/response/UploadImageResponse.java` xác nhận shape đó.
- `RecipeImageUploader.tsx` fallback sang `blob:` khi upload lỗi; `CreateRecipe.tsx` gửi nguyên URL trong request xuất bản.
- `RecipeService.publish` của FR-25 lưu tham chiếu ảnh vào `RECIPE_MEDIA`.

## Tái hiện

1. Mở form đăng bài bằng phiên Expert; làm request upload trả HTTP 503.
2. Chọn ảnh PNG hợp lệ; Frontend vẫn hiện ảnh xem trước có `src` bắt đầu bằng `blob:`.
3. Điền form hợp lệ và gửi xuất bản: trước sửa, payload chứa URL xem trước.

## Môi trường

Windows; đối chiếu source và generated OpenAPI cùng commit của baseline. Kiểm thử trình duyệt dùng API giả lập; chưa kiểm tra Azure hoặc SQL Server thật trong lượt này.

## Nguyên nhân

Frontend media client chưa đồng bộ với runtime contract. Fallback dùng cho preview được sử dụng như một tham chiếu upload thành công khi tích hợp direct publishing.

## Cách xử lý

Đã chỉnh media client theo contract `data/blobUrl/mimeType/sizeBytes`, đồng bộ type của thao tác đọc/cập nhật ảnh; form chặn xuất bản khi còn URL `blob:` và yêu cầu tải lại. Không đổi API Backend.

## Kiểm chứng

Hai test Playwright FR-25 đã pass: response upload đúng contract được giữ qua lỗi validation và gửi đúng URL khi xuất bản thành công; upload HTTP 503 vẫn cho preview nhưng không tạo request xuất bản. Backend vượt qua 43 test liên quan, gồm lưu thứ tự, ảnh bìa và recipeId. Đây là bằng chứng với API giả lập và unit test, chưa có bằng chứng nghiệm thu Azure/SQL Server thật.
