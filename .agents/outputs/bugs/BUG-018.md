# BUG-018 — Thay danh sách ảnh của Recipe Post đã có ảnh luôn trả 500

- **Trạng thái:** `RESOLVED`
- **Khu vực:** Backend/Recipe Media
- **Mức độ:** Medium
- **Ngữ cảnh phát hiện:** Viết test tích hợp SQL Server cho Issue #11 (quyền sửa ảnh) trên nhánh `feature/11-expert-recipe-publishing`, tách từ `develop` `3a1ab92`.
- **Nhánh/commit:** `develop` `3a1ab92`
- **Requirement/Issue/PR:** FR-14 (AC-14.2), FR-04 (US-04.2); Issue #11, #20; PR #96 (nguồn lỗi).
- **Ngày phát hiện:** 2026-10-11
- **Ngày cập nhật:** 2026-10-11

## Triệu chứng

`PUT /api/v1/recipes/{recipeId}/media` trả `500 INTERNAL_ERROR` khi Recipe Post đã có ảnh và danh sách mới dùng lại một `displayOrder` cũ (ví dụ thay ảnh bìa ở vị trí 1).

## Hành vi mong đợi

Tác giả thay được toàn bộ danh sách ảnh; ảnh cũ bị xóa, ảnh mới được lưu theo thứ tự gửi lên, response `200`.

## Hành vi thực tế

Response `500`; log Backend ghi `DataIntegrityViolationException: Violation of UNIQUE KEY constraint 'UQ_RECIPE_MEDIA_order'`. Danh sách ảnh không đổi.

## Bằng chứng

- `RecipeMediaService.setRecipeMedia` gọi `recipeMediaRepository.deleteByRecipeId(recipeId)` rồi `saveAll(...)` trong cùng transaction. Hibernate flush lệnh `INSERT` trước `DELETE`, nên dòng mới trùng `(recipe_id, display_order)` với dòng cũ chưa bị xóa.
- `RecipeMediaServiceTest` dùng mock repository nên không phát hiện; test tích hợp `RecipeMediaAuthorizationIntegrationTest.theExpertAuthorCanUploadReplaceAndDeleteTheirRecipeImages` trên mã `develop` nhận `500` thay vì `200`.

## Cách tái hiện

1. Recipe Post `PUBLISHED` có một ảnh `display_order = 1`.
2. Tác giả gửi `PUT /api/v1/recipes/{recipeId}/media` với một ảnh khác, `displayOrder = 1`, `isCover = true`.
3. Quan sát `500` và log vi phạm `UQ_RECIPE_MEDIA_order`.

## Môi trường và nguyên nhân gốc

- **Môi trường:** Spring Boot test với SQL Server 2019 (Testcontainers), `develop` `3a1ab92`.
- **Nguyên nhân gốc:** Thứ tự flush của Hibernate (insert trước delete) với derived delete `deleteByRecipeId` khi chưa flush.

## Xử lý và kiểm chứng

- **Xử lý:** Trên nhánh `feature/11-expert-recipe-publishing`, gọi `recipeMediaRepository.flush()` ngay sau `deleteByRecipeId` để lệnh xóa chạy trước khi lưu ảnh mới.
- **Kiểm chứng:** Sau khi thêm `flush()`, test tích hợp của tác giả chuyển từ `500` sang pass: `PUT` trả `200`, bảng `RECIPE_MEDIA` chỉ còn ảnh mới; `DELETE` sau đó xóa hết ảnh. Trên stack Docker Compose thật, tác giả thay ảnh bìa nhận `200` và bảng chỉ còn ảnh mới.
