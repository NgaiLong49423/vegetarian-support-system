## Triệu chứng, mong đợi và thực tế

Một nguyên liệu có thể xuất hiện trong nhiều dòng công thức theo các đơn vị khác nhau. Bộ chọn phải gửi một ID nguyên liệu duy nhất để Backend xử lý mọi dòng tương ứng. Khởi tạo từ preview và từ chi tiết đều dùng `ingredients.map`, gửi ID lặp và bị Backend từ chối với HTTP 400.

## Bằng chứng và tái hiện

Job Docker Development `120286025669` của run `39914860889` thất bại tại `shopping-list-real-stack.spec.ts:135`: mong đợi 200, nhận 400 khi thêm công thức thứ hai. Fixture có cùng `ingredientId` ở dòng gram và mililit. `RecipeShoppingListService` chủ động từ chối ID trùng, trong khi `AddRecipeShoppingDialog` không loại trùng lúc khởi tạo. Mở hộp thêm công thức có hai dòng cùng nguyên liệu rồi xác nhận để tái hiện.

## Môi trường và nguyên nhân

React, Spring Boot, SQL Server thật qua root Compose. Trạng thái khởi tạo chứa ID lặp; thao tác chọn tất cả đã dùng Set nhưng đường khởi tạo chưa áp dụng.

## Cách xử lý

Loại trùng ID tại cả ba đường khởi tạo từ preview/state và từ API chi tiết. Giữ nguyên các dòng đơn vị để hiển thị và giữ validation Backend.

## Kiểm chứng

Regression preview/chi tiết trong `shopping-recipes.spec.ts` đạt, xác nhận request chỉ chứa một ID dù hiển thị hai dòng đơn vị. `shopping-list-real-stack.spec.ts` qua root Compose và SQL Server thật đạt, gồm thêm công thức thứ hai và kiểm tra dữ liệu đóng góp. Bộ regression Frontend liên quan đạt 28/28 test. Chờ CI xác nhận trên commit mới.
