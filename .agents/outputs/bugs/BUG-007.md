# BUG-007: Migration đồng thuận dinh dưỡng lỗi trên SQL Server mới

- Trạng thái: RESOLVED
- Khu vực: Backend/Database migration
- Mức độ: High
- Ngày phát hiện: 2026-10-01
- Nhánh/commit: Chưa xác định
- Requirement/Issue/PR: FR-35 / Issue #78

## Triệu chứng

Backend không khởi động được trên SQL Server database mới do Flyway migration `V3__nutrition_profile_consent.sql` thất bại.

## Kỳ vọng

Flyway áp dụng V1, V2, V3 thành công trên database mới và Backend khởi động để phục vụ hồ sơ dinh dưỡng.

## Thực tế

Flyway dừng ở V3 với SQL Server error 207: `Invalid column name 'health_data_consent_at'` (log cũng báo `health_data_consent`). Backend không khởi động; bài Playwright chưa chạy.

## Bằng chứng

- Chạy runner E2E với database SQL Server Express mới `MamXanhDB_E2E`.
- V1 và V2 được áp dụng trước khi V3 lỗi.
- Backend stdout ghi `Failed to execute script V3__nutrition_profile_consent.sql`, lỗi SQL Server 207 khi thêm `CK_USER_health_data_consent_timestamp` tham chiếu hai cột vừa thêm.
- Runner xác nhận database tạm đã được xóa sau lỗi.

## Tái hiện

Tạo database SQL Server rỗng, khởi động Backend với Flyway bật và áp dụng `V3__nutrition_profile_consent.sql`.

## Môi trường

- Windows 11, Microsoft SQL Server Express 2019, SQL Server JDBC Driver 13.4.0, Spring Boot 4.1.1, Flyway 12.4.0.

## Nguyên nhân gốc

SQL Server phân tích check constraint trong cùng migration batch trước khi metadata của hai cột mới có hiệu lực; vì vậy constraint tham chiếu các cột vừa thêm bị lỗi 207.

## Cách xử lý

Đổi phần tạo check constraint trong `V3__nutrition_profile_consent.sql` sang dynamic SQL để SQL Server biên dịch constraint sau thao tác thêm hai cột.

## Kiểm chứng

Ngày 2026-10-01, chạy Playwright headed toàn bộ 13 bài với SQL Server Express database tạm sạch. Flyway áp dụng đủ V1–V3, Hibernate xác thực schema, luồng hồ sơ chạy qua API thật, xác minh các trường profile và consent trong DB trả `PASS`; sau kiểm thử database/login tạm được dọn thành công.
