# BUG-053 — Tìm nguyên liệu có dấu tiếng Việt trả rỗng dù có dữ liệu

- **Trạng thái:** `RESOLVED`
- **Khu vực:** Backend/Nutrition/SQL Server search
- **Mức độ:** Medium
- **Ngày phát hiện:** 2026-10-20
- **Ngày cập nhật:** 2026-10-21
- **Nhánh/commit:** `fix/142-verified-pro-payment`, `013c6ca`
- **Yêu cầu:** FR-18, FR-62; chưa có Bug Issue riêng.

## Bối cảnh, mong đợi và thực tế

CI #39435070985 có dữ liệu nguyên liệu ACTIVE và đếm nhóm đúng nhưng tìm qua API theo tên/nhóm tiếng Việt trả content rỗng. Phải tìm được bản ghi có sẵn, đồng thời không đưa nguyên liệu ngừng dùng hoặc trường quản trị ra API công khai.

## Bằng chứng và tái hiện

API local liệt kê 187 nguyên liệu. Tìm chính xác tên và nhóm của “Bánh mì nguyên cám” trả 1; tìm tương tự “Bánh phở”, “Bắp cải”, “Bắp cải tím” đều trả 0. `IngredientCatalogDatabaseIntegrationTest.publicIngredientBrowseListsActiveGroupsAndOmitsAdministrativeFields` thất bại với expected 1 / actual 0 trên SQL Server thật.

## Môi trường và nguyên nhân

Hibernate, SQL Server, baseline develop `d9be603`. Truy vấn LIKE ghép mẫu bằng CONCAT trong SQL có thể ép kiểu chuỗi làm mất ký tự tiếng Việt ngoài tập ký tự VARCHAR. Đang xác minh bằng regression giữ nguyên dữ liệu Unicode.

## Cách xử lý

Ghép wildcard trong service và bind nguyên mẫu Unicode, bỏ phép CONCAT phía SQL; giữ bộ lọc trạng thái, nhóm và phân trang. Không đổi tên fixture sang ASCII để né lỗi và không sửa dữ liệu nguyên liệu.

## Kiểm chứng

Ngày 21/10/2026: `IngredientCatalogServiceTest` (37 test) và `IngredientCatalogDatabaseIntegrationTest` (5 test) pass, giữ nguyên fixture tiếng Việt trên SQL Server thật. Sau build root Compose, HTTP tìm theo tên và nhóm trả “Bánh phở”: 1, “Bắp cải”: 2 (bao gồm “Bắp cải tím” theo phép tìm chứa từ khóa), “Bắp cải tím”: 1; trước sửa cả ba truy vấn đều trả 0.
